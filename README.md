# Лабораторная работа №6

## Разработка сценария нагрузочного тестирования с использованием Locust

### Цель работы

Разработать сценарий нагрузочного тестирования API с использованием Locust.

В лабораторной работе тестируются:

- OpenBMC Redfish API
- JSONPlaceholder
- wttr.in

## Структура проекта

- `locustfile.py` — сценарий нагрузочного тестирования
- `requirements.txt` — зависимости проекта
- `.gitignore` — файлы, которые не нужно загружать в Git
- `README.md` — описание лабораторной работы

## OpenBMC

OpenBMC запускался в QEMU на виртуальной платформе Romulus.

HTTPS-порт `443` OpenBMC был проброшен на локальный порт `8443`.

Адрес Redfish API:

    https://127.0.0.1:8443

Используемый endpoint:

    /redfish/v1/Systems/system

Из ответа также проверяется параметр:

    PowerState

### Проверка OpenBMC

Проверка корневого Redfish API:

    curl -k -u root:0penBmc https://127.0.0.1:8443/redfish/v1/

Проверка информации о системе:

    curl -k -u root:0penBmc https://127.0.0.1:8443/redfish/v1/Systems/system

## Установка

Создание виртуального окружения:

    python3 -m venv venv

Активация виртуального окружения:

    source venv/bin/activate

Установка зависимостей:

    pip install -r requirements.txt

## Запуск Locust

Запуск:

    locust

После запуска открыть в браузере:

    http://localhost:8089

## Сценарии нагрузки

В `locustfile.py` реализованы два класса виртуальных пользователей.

### OpenBMCUser

Выполняет:

- получение информации о системе
- проверку наличия поля `PowerState`

### PublicAPIUser

Выполняет:

- получение списка постов JSONPlaceholder
- получение погоды Новосибирска через wttr.in

## Проведённые тесты

Были проведены три теста:

- 10 пользователей, скорость запуска 2 пользователя/с
- 25 пользователей, скорость запуска 5 пользователей/с
- 50 пользователей, скорость запуска 10 пользователей/с

## Результаты

### 10 пользователей

OpenBMC работал без ошибок.

Среднее время ответа OpenBMC составляло примерно 2.6 секунды.

### 25 пользователей

Ошибок OpenBMC также не возникло.

Среднее время ответа увеличилось примерно до 5.9 секунды.

### 50 пользователей

OpenBMC продолжал работать без ошибок.

Среднее время ответа увеличилось примерно до 8.7 секунды.

При этой нагрузке появились ошибки у внешнего сервиса wttr.in.

## Вывод

В ходе лабораторной работы был разработан сценарий нагрузочного тестирования с использованием Locust.

OpenBMC успешно выдержал нагрузку в 10, 25 и 50 виртуальных пользователей без ошибок. При увеличении количества пользователей увеличивалось время ответа API, то есть производительность системы постепенно снижалась.

Публичные API также были протестированы. При высокой нагрузке наиболее нестабильно работал сервис wttr.in.
